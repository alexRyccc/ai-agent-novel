# 静态代码分析

## 目标

建立覆盖缺陷、规范、重复度的静态分析流水线并输出可行动的结论。

## 适用场景

- 引入静态分析
- 代码质量体检
- CI 质量门禁

## 工作流

1. 选定工具组合：SpotBugs（缺陷）、Checkstyle/PMD（规范）、CPD（重复度）。
2. 规则集以团队基线为准，先“报告不阻断”，收敛后再设门禁。
3. 跑全量扫描，按文件/模块聚合问题密度。
4. 定位热点：问题密度 top 10 文件优先治理。
5. 把门禁接入 CI，只对增量代码强制。

## 检查清单

- [ ] 规则集是否可解释（不用“全开”糊弄）
- [ ] 是否区分存量与增量
- [ ] 误报是否有抑制机制
- [ ] 扫描是否覆盖测试代码与构建脚本

## 产出要求

交付：工具配置 + 问题分布报告 + 热点文件清单 + CI 门禁规则。
