# 微服务拆分与边界设计

## 目标

给出有依据的服务边界、同步/异步交互方式与数据一致性方案。

## 适用场景

- 单体服务拆分
- 新服务边界评审
- 服务间耦合过重

## 工作流

1. 先按业务能力（而非技术分层）划边界，用领域事件识别聚合。
2. 明确每个服务的数据所有权：一个数据只有一个写入方。
3. 区分同步调用（需即时结果）与异步事件（可最终一致）。
4. 跨服务事务用 Saga / 本地消息表，禁止分布式事务硬扛全场景。
5. 定义服务契约（OpenAPI / 事件 schema）并纳入版本管理。

## 检查清单

- [ ] 是否存在多个服务写同一张表
- [ ] 服务间是否存在同步调用链过长（>3 跳）
- [ ] 是否设计了幂等与重试
- [ ] 是否有统一的可观测性（traceId 贯穿）
- [ ] 拆分后运维成本是否被评估

## 产出要求

交付：服务边界图 + 数据所有权表 + 交互方式（同步/异步）说明 + 一致性方案。
