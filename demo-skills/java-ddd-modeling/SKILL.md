# DDD 领域建模

## 目标

产出与业务语言对齐、聚合边界清晰的领域模型。

## 适用场景

- 新业务建模
- 贫血模型改造
- 领域概念混乱

## 工作流

1. 先整理统一语言（术语表），确保业务方与代码用词一致。
2. 识别聚合根：一个事务只修改一个聚合。
3. 值对象优先于实体（无标识、不可变、可替换）。
4. 领域行为放在领域对象内，避免 Service 变成过程式脚本。
5. 跨聚合协作通过领域事件或应用服务编排。

## 检查清单

- [ ] 聚合是否过大（导致锁竞争）
- [ ] 是否存在贫血模型（只有 getter/setter）
- [ ] 领域对象是否依赖了基础设施（应通过接口倒置）
- [ ] 不变量是否在聚合内被守护

## 产出要求

交付：术语表 + 聚合清单与边界说明 + 核心领域对象代码骨架。
