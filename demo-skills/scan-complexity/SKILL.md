# 圈复杂度与可测试性治理

## 目标

把高复杂度方法拆解为可独立测试的小单元。

## 适用场景

- 复杂度门禁超限
- 方法难以测试
- 嵌套过深

## 工作流

1. 统计圈复杂度（McCabe）与认知复杂度，定位超阈值方法。
2. 用卫语句（guard clause）消除深层嵌套。
3. 用策略模式/多态替换长 `switch` / `if-else` 链。
4. 把复杂条件表达式提取为命名良好的谓词方法。
5. 拆分后为每个小单元补单元测试。

## 检查清单

- [ ] 是否只是把代码拆散而没有降低总复杂度
- [ ] 拆分后是否引入更多跨类跳转（可读性反而下降）
- [ ] 是否有重复的条件判断未被合并
- [ ] 边界条件是否仍被覆盖

## 产出要求

交付：复杂度前后对比 + 重构后代码 + 新增测试覆盖情况。
