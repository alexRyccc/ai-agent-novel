# 代码坏味道识别

## 目标

识别长方法、大类、重复代码、过度耦合等坏味道，并给出重构顺序。

## 适用场景

- 重构前评估
- 代码评审
- 遗留系统治理

## 工作流

1. 先量化：方法长度、类行数、参数个数、圈复杂度、重复率。
2. 按“改动频率 × 复杂度”排序，高频高复杂才是重构重点。
3. 识别典型坏味道：长方法、霰弹式修改、依恋情结、数据泥团。
4. 每个坏味道给出具体重构手法（提取方法 / 移动方法 / 引入参数对象）。
5. 重构必须有小步可验证的测试网，禁止一次性大改。

## 检查清单

- [ ] 是否只按代码量排序而忽略改动频率
- [ ] 重构前是否有测试保护
- [ ] 是否一次性重构过大导致无法回滚
- [ ] 重构后行为是否等价（对外契约不变）

## 产出要求

交付：坏味道清单（含量化指标）+ 重构优先级 + 分步重构计划。
