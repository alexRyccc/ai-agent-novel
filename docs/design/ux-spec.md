# SkillForge 本地技能看板 · 体验设计规范（UX Spec）

> 版本：v1.0 ｜ 适用范围：多页控制台（SPA，单文件 HTML）｜ 作者：ux-lead
> 衔接：本规范在设计层与现有单文件实现 `sfx/_data/index_template.html` 保持同一套 `.sf-` 令牌与组件命名，视觉层由 visual-architect 落地，前端按本规范实现交互与路由。

---

## 0. 总览：设计原则与硬约束

### 0.1 硬约束（不可违反）
1. **零依赖、断网可用**：纯 `http.server` 渲染，单文件 HTML，CSS/JS 内联，无任何外部库、CDN、字体请求。
2. **单文件 SPA**：所有页面收进同一 HTML，推荐 **hash 路由 `#/xxx`**（避免服务端路由，兼容 `file://` 与任意静态托管）。
3. **后端契约已冻结**：仅 `GET /api/skills`、`GET /api/stats`、`POST /api/match` 三项可用。其余页面（详情 / 工作台 / 市场 / 设置 / 自报条）**当前无后端，先用前端 mock 数据搭结构与交互，后续只换数据源**。
4. **设计令牌单一来源**：颜色 / 间距 / 字号 / 圆角 / 阴影 / 动效一律走现有 `:root` 令牌，断点值（480/768/1200）集中写在文件底部 `@media` 里（CSS 不允许变量用于媒体查询条件）。
5. **动效收敛**：仅状态过渡，全部 `≤150ms`；`prefers-reduced-motion` 下关闭所有过渡与动画（已有规则，继续保持）。

### 0.2 体验原则（对照 Nielsen 启发式）
| 启发式 | 在本产品中的落地要求 |
|---|---|
| #1 系统状态可见 | 加载 / 空 / 错误 / 保存中 / 复制中 均有显式状态块；路由切换后焦点落点与页面标题同步 |
| #2 现实世界匹配 | 术语对齐 CLI（`sfx scan` / `sfx match` / `sfx serve`），不造新词 |
| #3 用户掌控与自由 | 筛选可一键清除、抽屉可关闭、编辑可撤销 / 重置、自报条可关闭 |
| #4 一致性与标准 | 全局复用同一套 `.sf-` 组件（状态块、卡片、按钮、复制、徽标），命名统一 |
| #5 防错 | 空任务拦截在提交前；破坏性操作（删除 / 部署）二次确认 |
| #6 识别而非回忆 | 侧边栏按"任务目标"分组；常用入口在首页快捷区；筛选态常驻可见 |
| #7 灵活高效 | 提供搜索 + 标签筛选 + 排序；键盘可达；专家用户可直达 hash 路由 |
| #8 极简美观 | 沿用现有深浅双主题与 4px 间距阶梯，不新增视觉语言 |
| #9 容错恢复 | 超时 / 网络 / 服务端三类错误分别给可操作提示与重试 |
| #10 帮助文档 | 空态 / 错误态内联操作指引（如"运行 `sfx scan`"），不弹窗打断 |

---

### 0.3 体验感升级要点（增强项）
在维持"零依赖 / 单文件 / 断网可用"硬约束的前提下，体验感从"能用"升级到"好用且高效"，核心落在 7 个点：
1. **微交互反馈**：按钮 `:active` 按压缩放、卡片 hover 轻微浮起（均 ≤150ms，`prefers-reduced-motion` 下关闭），让操作有"被响应"的实感，不靠弹窗。
2. **骨架屏 / 乐观更新**：异步（复制 / 保存 / mock 安装）先给占位或即时态，再落定结果，避免空白焦虑。
3. **空 / 错误态情感化**：真空态给插画感引导（"运行 `sfx scan` 开始"），筛选空态给换词建议；一律内联、不弹窗（对照 #10）。
4. **键盘效率**：`/` 聚焦搜索、`g l` 跳转技能库、`g o` 跳转概览、`Esc` 关闭抽屉 / 清空搜索——专家用户零鼠标可达。
5. **信息密度可调**：提供"紧凑 / 舒适"两档（localStorage 记忆），长列表用户可压缩行高。
6. **批量选择与视图切换**：列表 / 网格切换；多选后批量复制路径、批量加入工作台。
7. **关联技能推荐**：详情页基于 `tags` / `triggers` 的相似度，列"相关技能"，缩短发现路径（Nielsen #6）。

> 体验感增强一律复用现有 `.sf-` 令牌与动效时长，不引入新视觉语言（硬约束 #4 / #8）。

## 1. 信息架构（IA）

### 1.1 全局导航树（侧边栏分组 · 推荐方案）

**决策：侧边栏 = 按"用户任务目标"的页面导航，不做功能域 / 来源分组。**

```
SkillForge
├─ 概览        #/overview        （P1 首页：统计 + 快捷入口 + 最近 + 自报条）
├─ 技能库      #/library         （P2 列表：左侧分类 facet + 工具条 + 卡片网格）
├─ 路由试验台  #/lab             （P4 保留增强：任务 → 匹配卡）
├─ 工作台      #/workbench       （P5 Prompt 列表 → 编辑器 → 实时预览 → 保存）
├─ 团队市场    #/market          （P6 mock：网格 + 来源切换 + 筛选）
└─ 设置        #/settings        （P7 分组表单：偏好 / 数据源 / 关于）
```

**为什么这样分（对照需求里的两组候选维度）：**

- **候选 A：按功能域分组（Scan / Match / Prompt / 埋点 / 部署）** —— 这是"技能能力"的维度，更适合作为**筛选 facet**，而非顶层导航。把它当导航会让"埋点""部署"这种后台动作与浏览页并列，语义错乱，且后端未提供 `domain` 字段，分组会落空。
- **候选 B：按来源分组（本机 / 团队）** —— 在单文件离线场景下，**技能库内的条目 100% 来自本机**，"本机"分组无区分度；"团队"应独立成 P6「团队市场」页。来源因此不该作为库内分组。
- **推荐（按任务目标）**：用户进入看板是为了"看全局 / 找技能 / 试路由 / 写 Prompt / 逛市场 / 改设置"，导航与这 6 个目标一一对应，符合 Nielsen #6，也和现有页面结构平滑升级（现状已是概览+试验台+列表，只是补上缺失的几页并加壳）。

### 1.2 页面层级（P1–P7 + 详情）

```
P1 概览 ───────────────（入口页）
P2 技能库 ──┬─ P3 技能详情  #/library/:slug   （从列表进入，可深链）
P4 路由试验台
P5 工作台 ──┬─ 编辑器（列表项 → 编辑态，可深链 #/workbench/:id）
P6 团队市场
P7 设置
```

- **详情 / 编辑器支持深链**：`#/library/:slug`、`#/workbench/:id`，刷新可直接定位（mock 阶段用本地数据解析 slug/id）。
- **全局自报条**跨所有页常驻（见 1.3），不属于任何页层级。

### 1.3 全局自报条（自报条）位置与触发逻辑

**定位**：固定在 `<header>` 之下、`#sf-main` 之上的横条区域（`role="status"` + `aria-live="polite"`），宽度随内容区。它承担"系统主动向用户报告自身状态 + 用户一键反馈"两个职责，故名"自报"。

**触发优先级（自上而下，仅显示最高优先级的一条，多条排队）：**

| 级别 | 触发场景 | 视觉（复用令牌） | 动作 |
|---|---|---|---|
| error | `sfx serve` 失联 / 列表请求失败且无可回退数据 | `sf-state--error` 红左条 | 「重试」+「关闭」 |
| warn | 从未扫描（`last_scanned_at` 为空）/ 有新版本可更新 / 存在需上报的坏技能 | `sf-state--empty` 黄左条 | 「去扫描」或「查看」+「关闭」 |
| info | 扫描完成提示 / 复制成功等轻提示（轻提示优先走局部 toast，不占此条） | 中性条 | 「关闭」 |

**交互与关闭（详见 §4.3）：** 关闭按钮 `aria-label="关闭提示"`；关闭后写入 `localStorage` 按 `key+hash` 记忆，**本次会话不再自动弹出同类提示**（用户主动触发的不受此限）。

### 1.4 路由方案（hash）

- 模式：`#/overview` `#/library` `#/library/:slug` `#/lab` `#/workbench` `#/workbench/:id` `#/market` `#/settings`
- 解析：`hashchange` 驱动；未知路由回退 `#/overview`；带 `:slug/:id` 时解析参数后渲染。
- 深链刷新：mock 阶段从本地数据按 slug/id 还原；接后端后改为 `/api/skills?slug=` 等。
- 历史：浏览器原生 back/forward 即可（hash 天然支持），无需自建栈。
- 首屏不请求网络（沿用现状：数据内联 `__SKILLS__/__STATS__`），路由只切换视图。

## 2. 各页面布局与核心交互流程

> 统一约定：每页主区域 `<main id="sf-main" tabindex="-1">`；页内主标题用 `<h1>`（或 `sf-title`），区块用 `sf-panel` + `sf-panel-title`，状态用 `sf-state`（loading/empty/error）。

### P1 概览 / 首页（`#/overview`）
**布局（自上而下）：**
1. 全局自报条（§1.3）
2. 统计卡区（复用现有 `.sf-stats`：入库总数 / 已启用 / 最近扫描；窄屏三列已在 480 断点生效）
3. **快捷入口**：4 个主操作卡（去技能库 / 试路由 / 开工作台 / 逛市场），`sf-card` 变体，点击跳对应路由
4. **最近活动**：最近扫描到的 N 个技能（mock：取列表前 5；按 `last_scanned_at` 排序，后端补齐后切换）
5. 路由试验台**轻量入口卡片**（非完整版，避免首页过重）

**核心流程**：进入即见状态 → 点快捷卡进子页 → 最近技能可点进 `#/library/:slug`。

### P2 技能库（`#/library`）
**布局（≥768 两栏：左分类 facet + 右内容）：**
- **左栏 · 分类 facet**（窄屏收进抽屉，见 §5）：
  - 全部 / 按功能域（Scan/Match/Prompt/埋点/部署，由 tags 派生，后端补 `domain` 后切换）/ 按作者 / 按标签（多选）
  - facet 选中态用 `aria-pressed` 或勾选框，常驻显示当前筛选摘要
- **右栏 · 工具条 + 网格**：
  - 工具条：`sf-filter` 搜索（名称/摘要/标签子串）+ 排序下拉（默认"最近/相关度"，可选 名称A-Z / 版本 / 作者）+ 「清除筛选」+「重新加载」
  - 卡片网格：复用现有 `.sf-card`（头像/名称/版本·作者/自动摘要徽标/摘要 3 行截断/标签 `+n`/路径）；**整卡可点进入详情**（卡片包一层 `<a>` 或 `role="link"`，键盘可达）

**核心流程**：浏览/筛选 → 看到计数 `显示 x / 总` → 点卡片进 `#/library/:slug`。

### P3 技能详情（`#/library/:slug`）
**布局（≥1024 两栏：左元数据，右大区；窄屏单栏）：**
- **头部**：名称 + 版本 + 作者 + 「返回库」+ 「复制路径」按钮
- **元数据区**：slug、路径（`sf-path` + 复制）、摘要（完整，非截断）、标签（全部 `sf-tag`）、触发词（`triggers[]` 以 `sf-tag`/code 展示）、状态（启用/停用）
- **实时校验区**（可选，接后端后）：路径是否存在、摘要是否为自动生成（`summary_fallback` 徽标复用现有"自动摘要"）
- **操作**：复制路径（带成功/失败反馈，§4.2）、加入工作台（mock：写入本地草稿）、分享（mock）

**核心流程**：从列表进入 → 读完整信息 → 复制路径或加入工作台 → 返回。

### P4 路由试验台（`#/lab`，保留增强）
**沿用现状良好结构**，仅增强：
- 任务输入 → 提交（loading 用 `sf-spinner` + `aria-busy`）→ `POST /api/match` → 结果卡（`sf-match`：名称/得分 `sf-score`/原因/路径/复制）
- **增强点**：①结果卡可点进对应技能详情（`#/library/:slug`，需后端在 match 返回里带 slug，暂用 name 匹配）；②"阈值/模型"高级项折叠（mock 参数，接后端再接）；③历史最近任务下拉（localStorage）
- 错误三级（超时 / 网络 / 服务端）沿用现有 `renderMatchFailure` 文案，保持。

### P5 Prompt 工作台（`#/workbench`）
**三级结构：列表 → 编辑器 → 实时预览 → 保存指示。**
- **列表态**：左侧草稿/模板列表（`sf-card` 变体，含 名称/最后编辑时间/来源本机或团队），右侧空态引导"新建 Prompt"。
- **编辑态**（点列表项或新建）：
  - 左栏：表单（名称、描述、正文 `textarea`/`contenteditable`，支持变量 `{{var}}` 高亮）
  - 右栏：**实时预览**（随输入重渲染；mock 用本地模板引擎，接后端后调 `/api/render` 之类）
  - 底部工具栏：**保存**（显式，见 §4.2 保存反馈）、**重置**（撤销到上次保存，可逆）、**删除**（破坏性，二次确认）
- **保存指示**：未保存改动显示"未保存"点（Nielsen #1 状态可见）；保存中 spinner；保存成功 toast + 列表时间更新；保存失败回滚并提示重试。

### P6 团队市场（`#/market`，mock）
**布局（复用卡片网格）：**
- 顶部：来源切换「本机推荐 / 团队共享」（来源维度**只在此页**出现，印证 §1.1 来源不该进库内分组）+ 搜索 + 标签筛选 + 排序
- 网格：市场卡（名称/作者/评分/简介/「安装到本机」按钮，mock 写入本地草稿区）
- 空态 / 加载 / 错误同 §4.1；"安装"为 mock 动作，给出成功反馈，接后端后落库。

### P7 设置（`#/settings`）
**分组表单（`sf-panel` 分区 + `sf-lab-form`）：**
- 偏好：主题（跟随系统 / 深 / 浅，落 `localStorage`）、 Reduced-motion 提示、默认排序
- 数据源：本机 `home` 路径展示（只读）、扫描频率（mock）、"立即扫描"按钮（调 `sfx scan`，接后端）
- 关于：版本、本机数据说明、"断网可用"声明（复用 `sf-chip` 语义）
- 所有改动即时或"保存"提交；破坏性设置二次确认。

## 3. 分类与筛选方案

### 3.1 侧边栏分类维度对比与推荐

| 维度 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **按功能域**（Scan/Match/Prompt/埋点/部署） | 贴近"技能能力"，浏览目标清晰 | 后端无 `domain` 字段，需从 `tags` 派生或后端补字段 | **作为库内 facet 采用**，但现阶段用 tags 多值过滤兜底，domain 聚合为其上视图 |
| **按来源**（本机/团队） | 概念简单 | 库内 100% 本机，无区分度；"团队"应独立成市场页 | **不采用**为库内分组；来源仅出现在 P6 市场页切换 |

**推荐落法**：库内左栏 facet 以 **tags 多值筛选** 为最小可行实现（后端已给 `tags[]`），把"功能域"作为 tags 之上的可选聚合层（前端维护 `tag→domain` 映射表，后端补 `domain` 后无缝切换数据源）。这样既立刻可用，又为后端预留接口。

### 3.2 标签筛选：多选 / 单选 / 与搜索组合

- **多选 = OR（同一 facet 内）**：选 `Match` + `Prompt` → 命中任一。
- **跨 facet = AND**：功能域选 `Match` 且 作者选 `alice` → 取交集。
- **与搜索框 = AND**：搜索词（name/summary/tags 子串）在筛选结果上再过滤。
- **单选退化**：每个 facet 提供「全部」选项，等效清空该 facet。
- **筛选态常驻**：工具条显示 `显示 x / 总 y` + 「清除筛选」按钮（沿用现状 `sf-filter-clear`），符合 #3 用户掌控。

### 3.3 排序规则
- 默认：**最近 / 相关度**（库内默认按 `last_scanned_at` 降序；搜索时按匹配度）。
- 备选（下拉）：名称 A–Z / 版本号降序 / 作者。
- 排序与筛选、搜索叠加，结果实时重算（沿用 150ms 防抖，沿用现状 `FILTER_DEBOUNCE_MS`）。

---

### 3.4 高级筛选能力（增强项）
在 §3.2 / §3.3 的"多选 OR + 跨 facet AND + 搜索 AND + 基础排序"之上，补四组能力，让筛选从"够用"到"高效"，并引入命中率维度：

1. **多维度分面组合 + 计数 badge**：每个 facet 项后显示实时命中数（如 `Match（12）`），随其他条件变化即时更新；组合逻辑沿用 §3.2（同 facet OR、跨 facet AND、与搜索 AND）。计数帮助用户在多选前预判结果规模，避免"选空"焦虑。
2. **保存筛选视图 / 预设**：将当前"facet 选择 + 搜索词 + 排序"打包为命名视图（存 `localStorage`），一键切换；视图可序列化为 URL hash 参数，便于分享与深链（如 `#/library?view=myview`）。预设视图（如"我最近用的""高命中率"）作为出厂默认值。
3. **搜索增强**：①结果中**高亮命中词**（`<mark>` 复用现有强调色，非新增）；②输入时给**搜索建议 / 自动补全**（历史任务、技能名前缀）；③支持**模糊 + 拼音 / 首字母**匹配（如 `pp` → `Prompt`、拼音 `pipei` → `匹配`），降低拼写门槛。
4. **排序增强**：支持**多字段组合排序**（如 先按 作者 升序、再按 版本 降序），字段权重可在排序面板内拖拽调序；默认仍走 §3.3 的"最近 / 相关度"。
5. **命中率图标（新增维度 · SkillScore）**：引入 PRD §6.4 定义的匹配准确率 `score` 作为**新的筛选与排序维度**，视觉以 `.sf-score-badge` 分档（≥80 绿色 accent / 60–79 黄色 warn / <60 灰色 danger），**全部分档复用现有 `--sf-color-*` 令牌，不新增色彩语言**。库内可按"命中率区间"筛（如只看 ≥80 的高质量技能），排序亦可选"命中率降序"。

> 以上增强只改前端交互与 mock 数据层；接后端后，计数 / 命中率来自 `/api/skills` 聚合，保存视图仍以 hash 参数承载。

## 4. 状态与反馈

### 4.1 统一 loading / empty / error
- **复用现有** `.sf-state` 三态（`sf-state--loading` / `--empty` / `--error`），左条颜色区分（蓝/黄/红），全站一致。
- **loading**：旋转 `sf-spinner` + 文案；按钮进入 `disabled`+`aria-busy="true"`。
- **empty**：区分"真空"（从未扫描 → 指引 `sfx scan`）与"筛选空"（提示换词 / 清除筛选），沿用现状两套文案。
- **error**：三级分类（超时 / 网络 / 服务端），各自给**可操作下一步**（重试 / 确认 `sfx serve` / 看终端），复用 `SfxError.kind`。
- 列表请求失败时**保留上一屏数据 + 顶部 error 条**（沿用现状"页面仍显示刚才内联的技能"），不整页清空。

### 4.2 复制 / 保存 的成功与失败反馈
- **复制**（路径 / Prompt 正文）：按钮文案 `复制 → 已复制 / 复制失败`，`is-ok`/`is-fail` 态 2s 复位（复用现有 `flashCopyFeedback`）；同步 `aria-live` 轻提示"已复制到剪贴板"。剪贴板失败（非安全上下文）降级 `execCommand`，仍失败则提示手动选择。
- **保存**（工作台）：未保存显示"• 未保存"；保存中按钮 spinner + `aria-busy`；成功 → toast「已保存」+ 列表时间刷新 + 清除未保存点；失败 → 回滚内容 + error 条「保存失败，可重试」。**保存可逆**：提供「重置」回到上次保存版本（Nielsen #3）。

### 4.3 自报条交互与关闭
- 关闭按钮 `aria-label` 明确（"关闭：<原因>"更佳）；关闭写入 `localStorage[sf:dismiss:<key>]`。
- 同 key 在本次会话（或按 key 设定 TTL）内不再自动弹出；用户手动触发（如点"重新扫描"）不受限。
- 条内主操作按钮（重试 / 去扫描）执行对应动作并在完成后自动收起。
- 多优先级排队：error 覆盖 warn 覆盖 info，避免叠加噪音。

## 5. 响应式重排（沿用 480 / 768 / 1200）

**核心策略：侧边栏在 `<768` 折叠为抽屉/顶部，使现有 480/768 断点的"内容区网格规则"继续成立（不被侧边栏挤占）。**

| 断点 | 侧边栏 | 内容区 | 详情 / 工作台多栏 |
|---|---|---|---|
| **≥1200** | 固定左栏 240px（常驻） | `sf-content-max:1280` 居中；统计 3 列、技能网格 4 列 | 详情/工作台 双栏 |
| **768–1199** | 固定左栏（可收窄至 200px）或顶部水平 tab | 统计 3 列、网格 2 列（沿用 768 规则） | 详情/工作台 双栏 → 可降为单栏（≥1024 才双栏） |
| **480–767** | **抽屉**（汉堡触发，焦点陷阱，Esc 关闭）或顶部 tab 条 | 统计 3 列、网格 2 列 | 单栏（上下堆叠） |
| **<480** | 抽屉 / 顶部 | 统计保持 3 列或降单列、网格单列 | 单栏 |

**抽屉规范**：汉堡按钮 `aria-expanded` + `aria-controls` 指向抽屉；打开时焦点移入首个导航项，Tab 循环限制在抽屉内（focus trap），关闭后焦点回汉堡；`prefers-reduced-motion` 下无滑动，直接显隐。
**多栏降级**：详情/工作台用 CSS `grid` + `min-width:0` 容器，窄屏改为 `grid-template-columns:1fr`（单列堆叠），编辑器与预览上下排列，预览置于编辑区下方或折叠为可切换标签。

## 6. 无障碍（a11y）

### 6.1 键盘可达
- 全局 `sf-skip` 跳到 `#sf-main`（沿用）。
- 所有交互件可 Tab 到达；侧边栏抽屉焦点陷阱（§5）；卡片整卡可聚焦可回车进入。
- 搜索 `Esc` 清空（沿用现状）；筛选清除可聚焦。
- 不依赖鼠标悬停揭示关键信息（hover 仅作增强）。

### 6.2 ARIA 角色 / 标签
- 侧边栏 `nav aria-label="主导航"`；当前项 `aria-current="page"`。
- 自报条 `role="status" aria-live="polite"`（§1.3）。
- 路由试验结果区 `role="region" aria-live="polite"`（沿用）。
- 复制按钮 `aria-label="复制<对象>"`；图标 `aria-hidden="true"`；装饰 `sf-logo/sf-avatar` 加 `aria-hidden`。
- 表单控件均有 `<label>`（可见或 `sf-sr-only`），`aria-describedby` 关联提示。

### 6.3 SPA 路由切换：焦点管理 + aria-live
- 每次 `hashchange` 渲染后：**将焦点移到 `#sf-main`（`tabindex="-1"`）**，并同步 `document.title = "SkillForge · <页名>"`。
- 切换用**视觉隐藏的 `aria-live="polite"` 区域**播报"已进入<页名>"（避免读屏在大量 DOM 替换时丢失上下文）；不在每次切换都强提醒，仅在页面级切换播报，区块内更新复用各自 live 区域。
- 维护导航 `aria-current`，保证"我在哪"始终可见（Nielsen #1/#6）。
- 深链（`#/library/:slug`）直达时同样走上述焦点与标题流程。

### 6.4 reduced-motion 一致
- 沿用现有 `@media (prefers-reduced-motion: reduce)`：关闭所有 transition/animation，`sf-spinner` 转为静态半透明（不转），`sf-skip` 改为常显。
- 新增的抽屉滑入、toast 滑入、卡片入场等均遵守同一规则（用同一 reduced-motion 媒体查询包裹，或统一依赖令牌时长≤150ms 自然收敛）。
- 不提供"减少动效"开关与系统偏好冲突——以系统 `prefers-reduced-motion` 为准（设置页仅展示说明，不改写）。

## 7. 关键体验决策（结论先行）

1. **侧边栏按"任务目标"分页导航，不按功能域/来源分组；功能域仅作库内筛选 facet、来源仅出现在团队市场页** —— 避免无区分度的分组，导航与用户意图一一对应（Nielsen #6）。
2. **库内分类先用 `tags` 多值筛选兜底，功能域作为其上聚合视图** —— 在后端未提供 `domain` 字段的现实下，立即可用且为后端预留无损切换点。
3. **SPA 路由切换统一"焦点落到 `#sf-main` + 同步 `document.title` + 页面级 `aria-live` 播报"，并严格复用现有 `.sf-state`/`sf-skip`/`aria-live` 三件套** —— 保证多页化后无障碍基线不退化。
4. **筛选四维增强 + 命中率图标**：在"多选 OR / 跨 facet AND / 搜索 AND / 基础排序"基线之上，引入①分面计数 badge、②保存视图预设、③搜索高亮 / 建议 / 拼音模糊、④多字段组合排序四组增强；并以 PRD §6.4 的 `SkillScore` 命中率作为**新的筛选 / 排序维度**（`.sf-score-badge` 三档复用现有令牌）。目的：把"找技能"从逐页浏览升级为"精准分面 + 可复用视图 + 质量排序"的高效检索，同时不破坏零依赖 / 单文件 / 断网可用硬约束。
